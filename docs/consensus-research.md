# Consensus-через-голосование: как RevoAp считает согласие между LLM

*Версия 1.8.17 — май 2026. Документ ведётся вместе с `src/Consensus/`.
Сопровождает релиз, в котором лексический Jaccard заменён на семантическое
кластеризованное сравнение компонентов ответов моделей.*

> **TL;DR (по-русски).** Раньше RevoAp сравнивал ответы LLM как
> мешки слов и для одинаковых по смыслу, но по-разному сформулированных
> ответов выдавал ≈ 7–12 % согласия. Теперь движок извлекает из каждого
> ответа *семантические компоненты* (отдельные тезисы / пункты списка
> / предложения), сводит их в кросс-модельные кластеры по ключевым
> словам, символьным n-граммам и числам/именам собственным и считает
> согласие как долю содержания, которая покрыта общими кластерами. На
> том же примере (4 модели, русский ответ про кружку без дна) скоринг
> поднимается с 0.07–0.12 до 0.6–0.85 — то есть туда, где он реально
> должен быть.

> **TL;DR (English).** RevoAp used to compare model answers as raw
> token bags, which collapsed to ≈ 7–12 % overlap when several models
> answered the same idea using different surface words. v1.8.17 ships
> a semantic-component scorer: each answer is split into discrete
> components, components are clustered across models using lemma
> tokens, character 3-grams and numeric / named-entity hints, and the
> consensus score is the fraction of cross-model semantic content
> covered by shared clusters.

## 1. Постановка задачи

Ансамбли LLM сегодня — стандартный способ повысить надёжность
рассуждений: несколько разных моделей отвечают на один и тот же
запрос, и финальный ответ строится с учётом *согласованности*
их откликов. Чтобы это работало, нужна хорошая метрика согласия:
слишком мягкая — и галлюцинации одной модели проходят как «частичное
согласие»; слишком жёсткая — и любой парафраз превращается в
«конфликт».

В RevoAp это L3 шаг конвейера. Версии 1.0–1.8.16 использовали
парное Jaccard-сходство над токен-мешками отдельных claim'ов. Это
работает, когда модели отвечают коротко и одинаковыми терминами,
но даёт почти нулевые оценки на любых развёрнутых ответах.

## 3. Алгоритм семантического скоринга

Файл: [`src/Consensus/SemanticConsensusEngine.php`](../src/Consensus/SemanticConsensusEngine.php).

1. **Извлечение компонентов.** Для каждого ответа берутся claim'ы из
   `NormalizationService::normalize` плюс автоматически разрезанные
   маркдаун-буллеты. Из каждого компонента строится отпечаток:
   * нормализованные ключевые токены (Unicode-aware, стоп-слова русского
     и английского отфильтрованы, лёгкая дефлексия суффиксов);
   * символьные 3-граммы — компенсация морфологии для русского
     («кружка/кружку/кружкой» → пересекающиеся `_кру`, `руж`, `ужк` …);
   * числа и проценты;
   * именованные сущности по простому регэксп-эвристику (заглавная
     буква, последовательность Capitalized Words).
2. **Кросс-модельная кластеризация.** Жадно: каждый компонент
   присоединяется к лучшему по `similarity()` кластеру из *другой*
   модели; если ни один не подходит выше порога 0.42, заводится
   новый кластер. Sim — взвешенная сумма Jaccard по ключевым словам
   (0.55), Jaccard по 3-граммам (0.35), бонус за общие числа (0.05) и
   за общие сущности (0.05).
3. **Скор.** `score = Σ (weight × coverage_fraction) / Σ weight`, где
   coverage_fraction = доля моделей в кластере. К итоговому числу
   прибавляется +0.05 при наличии хотя бы одного единогласного кластера
   и вычитается до −0.15 на каждое прямое числовое противоречие.
4. **Статусы** (совместимы с предыдущими версиями `ConsensusResult`):
   * `agreement` при score ≥ 0.85;
   * `partial` при 0.55 ≤ score < 0.85;
   * `conflict` иначе.

Старый лексический backend сохранён под флагом
`pipeline.consensus.scoring = lexical_jaccard` в `config.php` и под
`consensus_scoring: "lexical_jaccard"` в JSON-определении skill'а.
Так оператор может сравнить два скоринга бок о бок на одной сессии.

## 4. Roundtrip с круговой защитой

Round-2, появившийся в v1.8.16, остаётся: при `agreement` + score ≥
порог пайплайн идёт прямо на L4; иначе каждой модели подбрасывают
ответы соседей и просят либо защитить, либо переисправить свой L1.
Новый skill `semantic-consensus-reasoning` явно структурирует
второй раунд по схеме из Pokharel et al.: каждая модель отдельно
указывает, какие peer-claims она *принимает*, какие *отвергает* и
почему.

## 5. Что НЕ сделано (честный scope)

Из работы Kallem (arXiv:2601.07245) мы НЕ включили в v1.8.17 полный
графовый набор: gradient-boosted trees поверх ручных фич и
graph-attention сеть над similarity-графом. Это требует внешнего ML
рантайма, который RevoAp пока не имеет. Текущая реализация — это
прямой локальный baseline с теми же входными фичами (semantic
similarity, clustering, lexical, numeric/entity), но финальная
агрегация — это аккуратная аналитическая формула, не выученная
модель. Расширение до learnable meta-learner оставляется как
будущая работа.

Также не подключены векторные эмбеддинги через провайдеров — это
запланировано как режим `consensus.semantic_mode = embedding|hybrid`,
сохраняющий тот же интерфейс `SemanticConsensusEngine::similarity()`.

## 7. Воспроизводимость

Конкретный кейс, который мотивировал релиз: 4 модели отвечают на
загадку про кружку без дна. До v1.8.17 L3 выдавал score ≈ 0.068,
0.085, 0.117 при том, что все четыре ответа описывали по сути одно
и то же множество идей. После v1.8.17 на тех же сырых ответах score
поднимается в диапазон partial/agreement благодаря тому, что
кросс-модельные кластеры покрывают подавляющее большинство claim'ов.
Регрессионные тесты на этот сценарий — в `tests/SmokeTest.php`
(блок `== v1.8.17: semantic consensus scoring ==`).
