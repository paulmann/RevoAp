# RevoAp v2.0.0 — Internationalisation

Five languages ship with the console: **English** (`en`), **German** (`de`),
**Russian** (`ru`), **Simplified Chinese** (`zh`) and **Arabic** (`ar`). Arabic
renders the whole interface right-to-left.

| | |
|---|---|
| Catalogues | `i18n/<code>.json` |
| Backend | `src/I18n/` (`Locale`, `PluralRules`, `MessageCatalog`, `Translator`, `LocaleNegotiator`) |
| Client | `assets/js/i18n.js` |
| API | `GET /api/i18n`, `GET /api/i18n/locales`, `GET /api/i18n/{locale}`, `GET /api/i18n/{locale}/coverage`, `POST /api/i18n/{locale}/key`, `POST /api/i18n/reload` |
| CLI | `php bin/revoap-i18n.php lint \| coverage \| extract \| diff <locale> \| add-key <k> <text>` |
| Tests | `tests/I18nTest.php` (194 assertions) |

## 1. Choosing a language

Precedence is the order users expect — each step is a stronger signal of
*intent* than the one below it. Implemented once in
`App\I18n\LocaleNegotiator::negotiate()` and mirrored in
`assets/js/i18n.js::detectLocale()` so the server and the client cannot
disagree about what the first paint should be.

| # | Signal | Persisted? | Why |
|---|---|---|---|
| 1 | `?lang=de` | **yes** | An explicit switch the user just clicked. The only unambiguous, immediate signal — and it must beat the cookie so a shared "look at this in Russian" link works. |
| 2 | `revoap_locale` cookie | no | The last choice this browser made. Readable by the inline boot script, so the first paint is already correct. |
| 3 | `X-Locale` header | no | Per-request override for API clients and the SPA's fetch layer. |
| 4 | `Accept-Language` | **no** | What the browser says the human prefers. Consulted only when the user has never chosen — exactly the first-visit case. |
| 5 | `ui.locale` / `app.locale` in config | no | The operator's site default. |
| 6 | `en` | no | Last resort, and the root of every fallback chain. |

**Why a header guess is never persisted.** Writing the negotiated
`Accept-Language` result into a cookie would pin the user to a language they
never asked for and make the browser's own preference permanently inert — they
could change their OS language and nothing would happen. Only an explicit
`?lang=` is a choice, and only a choice is remembered. `negotiate()` returns a
`remember` flag for exactly this distinction.

### Tag resolution

`Locale::fromTag()` accepts the shapes real clients send:

```
en  de  ru  zh  ar            exact
en-US  de-DE  ar-EG           region subtags
de_DE.UTF-8  ru_RU.utf8       POSIX with an encoding
ar_EG@euro  de_DE@euro        POSIX with a modifier
zh-Hans-CN  zh-Hant-TW        script subtags
EN  De-De                     case-insensitive (Accept-Language is)
```

and returns `null` — never a guess — for anything else.

**Traditional Chinese maps to Simplified, not to English.** That is deliberate:
a Simplified rendering of a Traditional reader's UI is still Chinese, whereas an
English one is a different language entirely. If `zh-TW` support is wanted, add
a `Locale::ChineseTW` case and `i18n/zh-TW.json`; nothing else changes.

**The parser is strict about what it strips.** A closed list of POSIX encodings
is removed after `.`, and a modifier after `@` — but not an arbitrary
`.json`/`.php` suffix. `Locale::fromTag('en.json')` returns `null`. This is not
exploitable either way (the file path is built from the enum's own `value`, never
from input), but a parser that accepts more than its documented grammar is a
parser that surprises someone later. Control characters are rejected *before*
trimming, because PHP's `trim()` strips NUL by default and would otherwise
launder `"en\0"` into `"en"`.

## 2. No flash of the wrong language

The catalogue is **embedded in the document**, not fetched:

```html
<script type="application/json" id="revoap-i18n-catalog">{"locale":"ar","dir":"rtl","messages":{…}}</script>
```

A round-trip would render English for ~200 ms and then reflow — and for Arabic,
flip the entire page direction after the user had started reading. The payload
is ~35 KB gzipped and caches with the document.

`<html lang dir data-theme class="dark">` are all written by PHP on the first
byte, then refined by the inline `assets/js/theme-boot.js` (which resolves
`system` and `?lang=`). `/api/i18n/{locale}` still exists and is used for
switching language without a reload and for the admin coverage report.

The embedded JSON is encoded with `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS |
JSON_HEX_QUOT`, so a `</script>` inside a translation cannot terminate the block
early. `tests/LiveSmoke.php` asserts that against the real response bytes.

## 3. Plurals

Rules are CLDR cardinal rules, implemented twice — `App\I18n\PluralRules` and
`pluralCategory()` in `assets/js/i18n.js` — and `tests/I18nTest.php` extracts the
JS implementation and runs the *same* fixture table through it under Node. The
two cannot drift without a test failing.

| Locale | Categories | Examples |
|---|---|---|
| `en`, `de` | `one`, `other` | 1 entry / 5 entries |
| `ru` | `one`, `few`, `many`, `other` | 1 запись / 2 записи / 5 записей |
| `zh` | `other` | no grammatical plural |
| `ar` | `zero`, `one`, `two`, `few`, `many`, `other` | لا مدخلات / مدخل واحد / مدخلان / ٣ مدخلات / ١١ مدخلًا / ١٠٠ مدخل |

The Russian and Arabic tables are where a naive implementation fails visibly:
Russian needs the mod-100 exception (`11` is `many`, not `one`) and Arabic needs
a grammatical dual.

```php
Translator::tn('audit.entries', 11, [], Locale::Russian);  // "11 записей"   (many)
Translator::tn('audit.entries', 21, [], Locale::Russian);  // "21 запись"    (one)
```

`count` and `n` are injected into the parameter list automatically, because
virtually every plural message wants to print the number.

**A dropped `{count}` is legal in `zero`/`one`/`two`.** Arabic spells "one
event" as حدث واحد with no digit at all; forcing `{count}` in would produce
"حدث واحد 1". The linter therefore treats an *unknown* placeholder as an error
(it would render literally on screen) and a *dropped* one outside those three
categories as a warning. `--strict` promotes the warning.

## 4. Message format

```
{version}            replaced by params['version']
{count, number}      locale-formatted number
{count, integer}     locale-formatted integer
{rate, percent}      0.421 → "42.1 %" / "42,1 %"
{at, date}           locale short date
{at, datetime}       locale date + time
{{literal}}          emits {literal}
```

An unknown placeholder is **left verbatim**. A visible `{model}` in the UI is a
bug report; an empty hole is not.

Formatting prefers `ext-intl` when loaded and falls back to a built-in table
otherwise — `ext-intl` is a `suggest`, not a `require`, because shared hosts
routinely lack it and a console that will not boot without it is a console that
will not boot. The fallback is locale-shaped, not merely unambiguous: `Y-m-d` is
correct ISO-8601 and wrong Chinese, so `zh` renders `2023年11月14日` either way.

Arabic uses **Latin digits**. That departs from the CLDR default for `ar`, and
the reason is operational: these are token counts and costs that operators
compare against provider dashboards, which use Latin digits.

## 5. Adding a key

```bash
php bin/revoap-i18n.php add-key models.batch_help 'Models that support …'
# edit i18n/{de,ru,zh,ar}.json
php bin/revoap-i18n.php lint      # CI gate
```

Or through the console: **Localization** tab → *Edit translation* (admin-gated).
That writes through `I18nController::setKey()`, which is atomic — the new
document goes to a sibling temp file and is renamed over the original, so a
crash mid-write cannot leave a truncated catalogue taking a whole locale
offline.

### What `lint` enforces

1. Every catalogue is a valid JSON object.
2. Every key of `en.json` exists in every other catalogue. A missing key renders
   as the raw key text in front of an operator, so this is not cosmetic.
3. Every pluralised key defines **every** CLDR category its language uses — and
   no category it does not. This is the bug a plain key-diff cannot catch.
4. No catalogue defines a key `en.json` lacks.
5. Placeholder sets match (unknown = error, dropped = warning outside
   `zero`/`one`/`two`).
6. No empty leaf, except `a11y.decorative`, where the empty string *is* the
   correct accessible name for a decorative icon.
7. `_meta.dir` agrees with `Locale::dir()`. A wrong value silently renders
   Arabic left-to-right.

`_meta.*` is catalogue metadata, not a translatable key, and is excluded from
coverage — its shape legitimately differs per language.

## 6. Right-to-left

`dir="rtl"` on `<html>` mirrors the entire shell, because every directional rule
in `ui/tokens.css`, `ui/shell.css` and `ui/tailwind.css` uses **logical**
properties (`inset-inline-start`, `padding-inline`, `border-inline-end`,
`margin-inline`). There is no `[dir="rtl"]` override stylesheet and no second
copy of any layout rule.

The few things that genuinely need flipping are handled explicitly:

* `.flip-rtl` — icons whose meaning is directional (an arrow, a chevron).
* `.switch:checked::after` — the thumb travels with `translateX`, which is not
  logical, so RTL negates it.
* `.num`, `time`, `.tabular` — get `unicode-bidi: isolate; direction: ltr`, so
  "1 234 токенов" cannot render as "токенов 234 1".
* Tabs arrow-key navigation maps `ArrowRight` to *previous* in RTL, because the
  tabs are laid out right-to-left.

Noto Sans Arabic is vendored (`assets/fonts/`) — Arabic coverage in system stacks
is unreliable and shaping quality varies enormously between faces.

## 7. Security

A translation is **operator-editable** through the admin Localization panel, so
it is user input.

* `Translator::t()` returns a plain string and does **not** escape — the caller
  decides whether the result goes to HTML, JSON, CSV or a log line.
  `TemplateHelper` escapes by default; `|raw` is opt-in per site.
* `assets/js/i18n.js` assigns translations through `textContent` and attribute
  setters. It has exactly **two** `innerHTML` assignments, both asserted by
  `tests/I18nTest.php`: the `<template>` parse sink inside `sanitizeHtml()` (a
  detached, inert DocumentFragment — the standard technique) and the single
  `data-i18n-html` call site, which is fed *by* `sanitizeHtml()`.
* `sanitizeHtml()` strips `script`, `iframe`, `object`, `embed`, `link`, `meta`,
  `base`, `form`, `input`, `style`; every `on*` handler; and `javascript:`,
  `data:text/html` and `vbscript:` URLs.
* Attribute writes from `data-i18n-attr` are limited to an allow-list
  (`aria-label`, `title`, `alt`, `placeholder`, …). Without it a stale catalogue
  entry could set `href` and turn a translation into a navigation hijack.
* `i18n/` carries an `.htaccess` (`Require all denied`) and the nginx hardening
  include refuses `/i18n/`, so catalogues are reachable only through
  `/api/i18n/{locale}` — the one door that applies the enum whitelist, the admin
  gate for writes, and the JSON encoding flags.

## 8. Client API

```js
import { t, tn, switchLocale, isRtl, formatCompact, timeAgo } from './i18n.js';

t('chat.send');                                  // "Send"
t('app.version', { version: '2.0.0' });          // "Version 2.0.0"
tn('audit.entries', 21);                         // "21 entries" / "21 запись"
await switchLocale('de');                        // live, no reload
await switchLocale('de', { reload: true });      // full navigation with ?lang=
```

`window.RevoApI18n` exposes the same surface (frozen) for the pre-v2 modules
that still reach for a global.

`reload: true` is the safe path when the page has already rendered server-side
content whose text cannot be re-translated in place — the Help panel, a shared
run.
