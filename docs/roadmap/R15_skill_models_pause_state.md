## Что должно получиться

### 1. Честный индикатор паузы

- Добавить в карточку активности состояние **`paused`**: статичная точка (кружок)
  жёлтого цвета вместо вращающегося кольца. Вращение должно **останавливаться**
  (`animation: none`), а не просто менять цвет.
- Пауза прогона (`app.js`, обработчик события паузы) должна выставлять именно
  `state: 'paused'` с подписью вроде `Paused - awaiting continue`.
- После «Continue» индикатор возвращается в `running` и снова вращается; завершение и
  ошибка - как сейчас (`completed` / `failed`).
- Смысл формулировки пользователя: воркер в этот момент **свободен** (работа ждёт
  команды), и интерфейс обязан показывать это спокойной жёлтой точкой, а не «что-то
  происходит». Не показывать вращение, пока прогон стоит на паузе.
- Если на странице статуса воркера есть собственный бейдж состояния (`WORKING` и т.п.) -
  он не должен противоречить: при простое и наличии задания на паузе состояние читается
  как ожидание, а не как работа.

### 2. Список моделей выбранного скилла - для всех скиллов

- Левый столбец при выборе любого Consensus skill (включая **Default**) показывает
  список моделей, привязанных к этому скиллу/пресету.
- Сейчас это работает только для Mathematics. Найти причину (частный случай по слагу
  пресета, пустой ответ каталога, потерянная привязка) и устранить **общую** причину, а
  не добавить второй частный случай.
- Если у скилла нет привязанных моделей - честно показать это словами (как уже сделано в
  `setConsensusSkillNote`), а не пустой столбец.

### 3. Поиск по каталогу вместо «Show all models»

- Переименовать чекбокс: вместо «Show all models» - подпись про **поиск по всем моделям**
  (в англоязычном интерфейсе приложения, например `Search all models`).
- Поведение: при включённом поиске показываются **только модели, попавшие в поиск**, и
  **не более 10** строк. Пустой поиск при включённом режиме - либо пусто с пояснением,
  либо подсказка начать ввод; главное - не вываливать весь каталог.
- Устранить **зависание** при выставлении чекбокса (найти реальную причину: лишний
  пересборка/рекурсия/тяжёлый пересчёт на каждое изменение; локально это должно
  проверяться харнессом, а не глазами).

### 4. "+ add model" должен добавлять модель

- Клик по модели в окне выбора добавляет её в пул и **не закрывает окно впустую**;
  выбор виден в списке немедленно.
- Найти реальную причину: обработчик теряет ссылку/событие, либо закрытие окна
  происходит раньше записи выбора. Исправить причину, а не подпереть таймером.

### 5. Кнопка "Save" - сохранение для скилла

- В блоке выбора моделей появляется кнопка **Save**, которая сохраняет выбранный пул
  **для выбранного Consensus skill** (через его пресет домена), а не только в текущем
  запросе Chat.
- После сохранения выбор переживает перезагрузку страницы и применяется при следующем
  выборе этого скилла.
- Кнопка честно сообщает результат: сохранено / нечего сохранять / ошибка с причиной.
  Молчаливого «нажал и ничего» быть не должно.

## Правила репозитория (обязательны)

- PHP: `declare(strict_types=1)`, `final class`, PHPDoc; без новых зависимостей Composer.
- JS: только `el()` / `textContent`; **`innerHTML` запрещён**.
- CSS: только существующие токены (`tests/CssTokensTest.php`); новый токен - сразу в обе
  темы.
- `node --check` на `.js` с ESM ничего не проверяет (всегда 0) - проверять копией `.mjs`.
- Харнессы запускать с `node --experimental-vm-modules`.
- Локальный PHP без `ext-curl` - проверка на фикстурах; реальный HTTP - на живом сайте.
- **Не выкладывать на сервер**: деплой делает координатор, не исполнитель.
- Не трогать: `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`,
  `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Не выполнять git-операции.
