# R8 — Экспорт и публикация результатов (MD/PDF, сравнение прогонов)

ROLE: Senior full-stack engineer specialised in document generation and diffing (PHP 8.5 + vanilla JS). Ты умеешь сделать переносимый результат, который читается вне интерфейса.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок. Прогон порождает: вопрос, состав участников и арбитра, шаги L1…L4 с ответами моделей, вердикт консенсуса, финальный ответ, статистику (стоимость, задержки, попадания в кеш). Всё это уже сохранено и отображается в History.

## Что уже есть

- История: `council_sessions`, `council_steps`, `council_model_responses`, `pipeline_events`; `src/History/HistoryService.php`; вкладка History с деталями прогона.
- Публикация: share-механизм (публичная ссылка на прогон) и страница share.
- Копирование: пары кнопок «Copy / Copy MD» на карточках (вопрос, шаги, финальный ответ) — `assets/js/copy-buttons.js` (файл менять нельзя, использовать как есть).
- Финальный ответ и карточка вопроса уже содержат состав и арбитра.

## Цель

Результат прогона можно вынести из интерфейса и сравнить с другим прогоном.

## Объём работ

1. **Экспорт прогона** — Markdown и PDF: тема, дата, совет и домен, состав участников, арбитр, шаги по слоям с ответами моделей, вердикт L3, финальный ответ, статистика (стоимость, задержки, кеш). Один и тот же состав в обоих форматах.
2. **Честность экспорта** — если шаг провалился или ответа нет, это видно в документе, а не пропущено; заглушка помечается как заглушка.
3. **Публикация** — существующая ссылка дополняется возможностью отозвать и явно показывает, что публикуется (состав, ответ, шаги) — по умолчанию публикация закрыта.
4. **Сравнение двух прогонов** — рядом: вопрос, состав, арбитр, вердикт, финальный ответ, стоимость и время; различия подчёркнуты. Применимо к прогонам с одинаковым или близким вопросом.
5. **Читаемость вне интерфейса** — документ должен быть понятен без ReVoAp: у каждого блока есть заголовок, у моделей — провайдер, у вердикта — словесное объяснение.

## Вне объёма

Внешние редакторы документов, публикация в сторонние сервисы, экспорт всей истории целиком (может стать отдельным пунктом).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. Если PDF требует библиотеки — сначала искать решение средствами проекта (HTML → печатная версия), и только потом предлагать минимальную зависимость с обоснованием.
- JS: `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Публичные контракты API только дополнять; share-ссылки не должны ломать уже выданные.

## Критерии приёмки

- Экспорт содержит состав, арбитра, шаги и статистику; читается вне интерфейса.
- Провалившиеся шаги и заглушки видны в документе.
- Сравнение двух прогонов показывает различия по составу, вердикту, ответу и стоимости.
- Публикация по умолчанию закрыта и отзывается.
