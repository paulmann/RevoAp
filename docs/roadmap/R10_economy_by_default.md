# R10 — Экономия по умолчанию: пакет и кеш там, где они реально выгодны

ROLE: Senior engineer specialised in LLM cost optimisation — batching and prompt caching — with strong PHP 8.5 and measured, non-fabricated economics. Ты умеешь считать экономию по фактическим данным и не превращаешь оптимизацию в навязанное поведение.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок. Есть два рычага стоимости:

- **Кеш промптов** (`src/Connectors/PromptCache/{Capability,Capabilities,Policy,Plan,Planner}.php`): применение в единой воронке `AbstractConnector::assembleChatRequest()` (общей для синхронного и пакетного пути), чтение `cache_discount` и токенов кеша в двух диалектах, настройки `prompt_cache` и карточка в Settings. У части провайдеров кеш автоматический, у Anthropic нужны явные точки останова (не более четырёх, TTL 5 минут или 1 час), у Gemini значима только последняя точка.
- **Пакетный режим** (`src/Batch/*`, `src/Connectors/Batch/*`): прогон с `run_mode = 'batch'`, окно провайдера до 24 часов, статусы `validating`/`in_progress`/`completed`/`failed`/`cancelled`, кнопка отмены, готовность в boot-config (`batch.ready`).

Данные для расчётов: `council_steps`, `council_model_responses`, `PIPELINE_DONE.stats.per_layer` (`cost`, `latency_ms`, `total_tokens`, `cached_tokens`), `cache_discount`.

## Цель

Там, где дешёвый путь действительно выгоден, приложение должно его предлагать — с оценкой экономии, без самовольной задержки ответа.

## Объём работ

1. **Классификатор «неспешной» задачи** — чистая функция на существующих сигналах (совет/скилл, число участников, история длительности и стоимости похожих прогонов, текущий режим). Выход: рекомендация «пакетом» / «синхронно» **с причиной текстом**. Никаких автопереключений.
2. **Оценка экономии до запуска** — от кеша (будет ли поставлена точка останова по плану, плюс фактическая доля попаданий по истории) и от пакета (документированная разница цены, ожидаемое время по истории). Оценка показывается рядом с составом и подписывается как оценка.
3. **Автоподбор политики кеша по измеренному результату** — пороги и TTL берутся из документированных минимумов провайдера (уже в `Capabilities`), далее корректируются фактом: если за N прогонов попаданий нет, приложение **предлагает** выключить кеш для этой модели (у Anthropic запись стоит 1.25×); предложение логируется, решение остаётся за оператором.
4. **Единая настройка «экономный режим»** — три уровня: `off` (сегодняшнее поведение), `suggest` (рекомендовать и показывать оценку), `prefer` (включать пакет и кеш там, где безопасно, оставляя переключатель). Видна в Settings и в карточке прогона.
5. **Учёт экономии** — строка на прогон: потрачено, сэкономлено кешем, сэкономлено пакетом (перекликается с R-5).
6. **Байт-в-байт совместимость** — при `off` тело запроса обязано остаться прежним (для кеша это уже проверено тестом — сохранить это свойство).

## Вне объёма

Дашборд расходов за период (R-5), оценка стоимости следующего прогона (R-1), собственный планировщик пакетов (R-14).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. JS: `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Для семейств без документированного кеша поведение не менять и ничего не обещать (текущее правило сохранить).
- Публичные контракты API только дополнять.

## Критерии приёмки

- Для типовой задачи видно предложение и оценку экономии до запуска; после — фактические цифры.
- Отказ от предложения не меняет поведение; уровень `off` полностью возвращает сегодняшнее поведение (проверяется тестом).
- При нулевой доле попаданий приложение предлагает перестать платить за запись в кеш.
- Рекомендация пакета никогда не превращается в самовольную задержку.
