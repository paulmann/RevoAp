# R7 — Панель здоровья системы с починкой в один клик

ROLE: Senior SRE-minded PHP engineer — ops automation with a safety-first approach to remediation. Ты умеешь диагностировать систему и не сломать её «починкой».

## Контекст проекта

ReVoAp — self-hosted консенсус-движок (PHP 8.5, Debian + FastPanel, nginx + PHP-FPM, Percona 8.0, воркер под systemd). Развёртывание — через `deploy/host/deploy.ps1`; бэкапы в `/root/revoap-backups/`.

## Что уже есть (и что уже болело на боевом)

- Устаревший код воркера: `WorkerHealthService` отдаёт `code_state` (`current` / `stale` / `unknown`), `code_newest_at`, `code_newest_file`; есть баннер с командой перезапуска и подсказка при `Call to undefined method`.
- Миграции и версии: `MigrationManager`, `SchemaManager`, `app_config` (`schema.version`, `table_version.<таблица>`), вкладка Settings → Migrations с «Apply Migrations».
- Права: записываемые каталоги (`var/`, `runtime/`, `logs/`), владелец `revoap_com_usr3245:revoap_com_usr3245`; ранее исправлялись права `666` после заливки.
- Каталог моделей: `var/config/runtime.json` (`models[]`, `active`), потолок `models.catalog.max_rows`, инвариант «пул, пресеты и связанные роли ⊆ активный каталог» (проверяется актуализацией).
- БД: `Database::isGoneAway()` распознаёт 1053/08S01/2006/2013/2002; воркер пишет переподключения (`db.reconnected`).
- Диагностика воркера: `/api/health/worker`, `last_job`, presence-heartbeat.

## Цель

Один экран: что не так в системе, почему это важно и что нажать. Плюс компактный чек-лист первого запуска для новой установки.

## Объём работ

1. **Проверки состояния** (каждая — с человеческим объяснением и уровнем важности): версия кода воркера против выложенного; состояние миграций и версий схемы; права на записываемые каталоги; свежесть каталога моделей; инвариант «пул и роли ⊆ активный каталог»; счётчик переподключений к БД; наличие ключей коннекторов; доступность ext-curl для пакетного и кеш-контуров.
2. **Действия** рядом с каждой проблемой, идемпотентные и подтверждаемые: перезапустить воркер (только если unit объявляет авто-перезапуск), применить миграции, поправить права, обновить каталог (Actualize), пересобрать пул.
3. **Чек-лист первого запуска** — шаги с отметками: ключи коннекторов → каталог моделей → актуализация пресетов → пробный прогон → воркер в автозапуске.
4. **Безопасность** — никаких «тихих» починок: перед изменением показать, что именно будет сделано; после — перечитать состояние и показать результат; всё — в журнал.
5. **Никаких ложных тревог** — если данных для проверки нет (например, БД недоступна), писать «неизвестно», а не «всё хорошо».

## Вне объёма

Автоматический ремонт без человека, мониторинг внешних сервисов, алертинг (это R-6).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. JS: `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены.
- Опасные операции — только через существующие admin-гейты (`AdminAuth::gateState()`, настройка `Protect_Settings_by_Admin_Key`); никаких обходов авторизации.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Не выполнять команды оболочки из PHP без крайней необходимости; где можно — использовать существующие сервисы приложения.

## Критерии приёмки

- Каждая проверка объясняет проблему и предлагает действие; «неизвестно» отличается от «норма».
- После действия состояние перечитывается, результат показан честно.
- Панель не может изменить состояние без подтверждения и без записи в журнал.
- Чек-лист первого запуска проходится на чистой установке.

## Проверка

```
php -l <изменённые .php>
php tests/WorkerCodeStateTest.php       # 49 / 0
php tests/WorkerStatusTest.php          # 157 / 0
php tests/AdminKeyProtectionTest.php    # 84 / 0
php tests/TerminalStatusTest.php        # 43 / 0
php tests/SmokeTest.php                 # 1534 / 54, набор падений не растёт
php tests/CssTokensTest.php             # 24 / 0
```
Новое: каждая проверка состояния (норма / проблема / неизвестно) — тестом; идемпотентность действий — повторным вызовом; отсутствие прав на запись не должно ронять панель.

## Заливка

`. \deploy\host\deploy.ps1 -Mode plan | -Mode deploy`; после заливки панель обязана показать `code_state = current`. Откат — `-Mode rollback -BackupId <id>`.

## Отчёт исполнителя

Список проверок и их пороги, что именно делает каждое действие, что нельзя откатить автоматически, команды с exit-кодами, что не проверено (боевая система).
