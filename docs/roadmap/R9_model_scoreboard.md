# R9 — Досье моделей: успешность, задержки, цена, поведение в кеше

ROLE: Senior data engineer with frontend craft (PHP 8.5 + vanilla JS), statistics-literate. Ты умеешь показать цифры так, чтобы по ним принимали решения, и честно пишешь «данных мало».

## Контекст проекта

ReVoAp — self-hosted консенсус-движок. Каталог моделей живёт в `var/config/runtime.json` (`models[]` с `active`, метаданными совместимости и признаком batch-only), вкладка Models управляет каталогом и пресетами, левая панель чата выбирает пул.

## Что уже есть

- Журнал: `council_steps` (модель, провайдер, слой, статус, длительность, токены, `cache_*`), `council_model_responses`, `pipeline_events` (`L1_RESPONSE`, `L1_FAILED`, `PIPELINE_DONE.stats.per_layer`).
- Статистика: `src/Stats/*`, вкладка Statistic, API статистики.
- Каталог: признак batch-способности (провайдерский список), признак «строка устарела» (`stale`), потолок `models.catalog.max_rows`.
- Привязка семейств/версий: `src/Models/ProviderFamily.php`, `src/Models/ModelVersion.php`.
- Актуализация (`ModelsActualizer`) уже назначает пул по доменам.

## Цель

Там, где модель выбирают, рядом с её именем должны быть её фактические показатели — успешность, задержка, цена, поведение в кеше — за выбранный период.

## Объём работ

1. **Метрики по модели** из журнала: доля успешных вызовов, медиана и хвост (p95) задержки, стоимость за тысячу токенов (по фактически возвращённой провайдером стоимости), попадания в кеш (доля и экономия), частота отказов и повторов, участие в арбитраже/синтезе.
2. **Показ в каталоге и в списке выбора** — компактно, не ломая существующую разметку комбобокса; отдельная колонка/строка в таблице вкладки Models и подсказка в списке моделей.
3. **Период и объём выборки** — выбор периода (день/неделя/месяц/всё время) и обязательное указание числа вызовов; при малой выборке — «данных мало», без рейтинга.
4. **Сравнение только внутри домена** — показатели модели в математике и в общем домене не смешивать; при показе вне домена явно это указывать.
5. **Никаких обещаний** — метрики берутся из журнала; если провайдер не сообщил стоимость или токены кеша, писать «не сообщено».

## Вне объёма

Автоматическое влияние метрик на состав пула (это R-3), публичные рейтинги между пользователями.

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. JS: `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены из обеих тем.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Тяжёлые агрегаты не должны считаться на каждый запрос левой панели: использовать существующую статистику/кэш приложения и явно описать, где считается.

## Критерии приёмки

- Рядом с моделью видны показатели за выбранный период и число вызовов.
- При малой выборке рейтинг не показывается, а пишется «данных мало».
- «Не сообщено» отличается от нуля.
- Показатели сходятся с журналом шагов и ответов.
