# R1 — Прозрачность прогона до отправки: участники, арбитр, оценка стоимости и времени

ROLE: Senior product engineer — vanilla-JS (ES modules) frontend plus PHP 8.5 backend, with operator-tooling UX judgement. Ты умеешь превращать уже собранные сервером факты в честный интерфейс и не выдумываешь данные, которых нет.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок (PHP 8.5, без фреймворка, front controller `index.php`, модули `App\...` в `src/`, vanilla ES modules в `assets/js/`, воркер под systemd: `revoap-worker`, `revoap-worker@1`, `revoap-worker@2`). Пайплайн: L0 (скилл и опции) → L1 (веер моделей) → L2 (нормализация) → L3 (консенсус, арбитр) → L4 (синтез). События пишутся в `pipeline_events`, шаги — в `council_steps`, ответы моделей — в `council_model_responses`.

## Что уже есть (опираться на это, не дублировать)

- `renderQueryCard(query, info)` в `assets/js/pipeline.js` рисует карточку вопроса; вызывается из `assets/js/app.js` при отправке. Уже показывает состав («Participants (N) — as requested / as resolved by the server»), арбитра («Arbiter: model (provider) — role») и расхождение между запрошенным и разрешённым составом.
- Событие `L0_OPTIONS` (`src/Pipeline/PipelineEngine.php`) несёт `selected_models`, `selection_diagnostic` (источник, slug/имя пресета, отклонённые записи с причинами) и `arbiter` / `arbiter_source` (`preset` | `config` | `none`).
- `PIPELINE_DONE` несёт `stats.per_layer.*` с `cost`, `latency_ms`, `total_tokens`, `cached_tokens`.
- Статистика: `src/Stats/{StatsCollector,SessionStats,TokenUsage}.php`, `StatisticsController`, вкладка Statistic.
- Пресеты консенсуса: `domain_presets.definition_json` (`models`, `arbiter`, `skill_slug`); `/api/consensus/skills` отдаёт на каждый скилл `preset`, `models`, `arbiter`, `uses_user_pool`.

## Цель

Оператор должен **до** отправки видеть: кто участвует, кто арбитр, сколько это примерно будет стоить и сколько времени займёт — а после прогона видеть фактическое рядом с оценкой.

## Объём работ

1. **Оценка стоимости** — по истории: для каждой модели в пуле взять медианную стоимость и медианную задержку на похожий объём промпта (использовать `council_steps`/`council_model_responses`), сложить по слоям L1…L4 с учётом лимита циклов; выдать **диапазон** и подписать его как оценку.
2. **Оценка времени** — та же история, но по задержкам; отдельно честно показать, что при пакетном режиме оценка другая (окно до 24 часов).
3. **Необязательный потолок** — настройка «не запускать прогон дороже X»: превышение → предупреждение с тремя исходами (продолжить, уменьшить пул, отменить). Потолок не должен ничего блокировать молча.
4. **Сверка после прогона** — когда приходит `PIPELINE_DONE`, в той же карточке показать факт: стоимость, время, попадания в кеш, рядом с прежней оценкой.
5. **Честность при отсутствии данных** — если истории по модели нет, писать «оценки нет — модель новая», а не ноль.

## Вне объёма

Дашборд расходов за период (это R-5), автоматический выбор дешевего режима (R-10), редактор пресетов (R-4).

## Ограничения и конвенции репозитория

- Стиль PHP: `declare(strict_types=1)`, `final class`, PHPDoc; никаких новых Composer-зависимостей; git-операций не выполнять.
- JS: рендер только через `el()` / `textContent`; **`innerHTML` запрещён** (это проверяется харнессом).
- CSS: только существующие токены из `assets/css/themes/{dark,light}.css`, новый токен заводить в **обе** темы (`tests/CssTokensTest.php`).
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Публичные контракты существующих API не ломать — только добавления.
- `node --check assets/js/*.js` для ESM **всегда даёт 0** — проверять через копии `.mjs`.

## Критерии приёмки

- До отправки видны участники, арбитр и оценка (диапазон, помеченный как оценка).
- После прогона в карточке видны фактические цифры, и видно расхождение с оценкой.
- При отсутствии истории по модели интерфейс говорит об этом, а не показывает нули.
- Потолок стоимости работает как предупреждение с выбором, а не как молчаливый отказ.

## Заливка

```
.\deploy\host\deploy.ps1 -Mode plan      # только изменённые файлы
.\deploy\host\deploy.ps1 -Mode deploy    # резервная копия + заливка + php -l + перезапуск
.\deploy\host\deploy.ps1 -Mode rollback -BackupId <id>
```
После заливки воркеры перезапускаются автоматически; учти, что статика отдаётся через `open_file_cache` и обновляется в течение примерно минуты.
