# R2 — Один экран «что случилось и что нажать»: диагностика прогона с действиями

ROLE: Senior full-stack engineer specialised in observability and incident UX (PHP 8.5 + vanilla JS). Ты умеешь из разрозненных фактов собрать один внятный экран и довести оператора до решения, а не до чтения логов.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок (PHP 8.5, без фреймворка; воркер под systemd; пайплайн L0…L4; события в `pipeline_events`, шаги в `council_steps`). Прогон идёт в воркере, задача живёт в `revoap_jobs` (`payload.kind`: `pipeline`, `models_actualize`, `batch_pipeline`).

## Что уже есть

- `PipelineEngine::resolveTerminalVerdict()` выводит терминальный статус из **фактов**: провал шага L4, события `L1_NO_RESULTS` / `L1_NO_AVAILABLE_MODELS`, непустой пул, разрешившийся в ноль моделей, пустой или заглушечный ответ. В результат и `PIPELINE_DONE` отдаются `status`, `status_reason`, `status_detail`, `status_role`.
- `preflightRun()` — предполётная проверка: пул, синтез, арбитр, анализатор против активного каталога; события `PIPELINE_PREFLIGHT` / `PIPELINE_PREFLIGHT_FAILED` называют роль, модель и причину (`not_in_catalog`, `connector_unavailable`, `batch_only`, `arbiter_model_not_served`).
- `selection_diagnostic` в `L0_OPTIONS` перечисляет отклонённые записи с причинами.
- `WorkerHealthService` отдаёт `code_state` / `code_newest_at` / `code_newest_file`, `last_job` (статус, длительность, модели, ошибка), `latest_heartbeat_source`.
- `SessionCompletionService` умеет достраивать/повторять синтез; в History есть кнопки «Re-run synthesis (L4)» и «Finish session».
- Раздел History показывает статус прогона; Raw-карточки событий содержат исходные записи.

## Цель

Один блок диагностики прогона: причина человеческим языком, что именно проверялось, и **кнопки действий**, которые эту причину устраняют.

## Объём работ

1. **Собрать факты в один блок** — статус, причина, роль, модель; отклонённые записи с причинами; результат предполётной проверки; для пакетного прогона — фаза и статус провайдера.
2. **Классификация причин** — свести все известные причины (`pool_no_usable_models`, `l1_no_results`, `l4_synthesis_failed`, `answer_empty`, `arbiter_model_not_served`, устаревший код воркера, неприменённая миграция, недоступный коннектор) к конечному списку с человеческим текстом и **одним** рекомендуемым действием каждая.
3. **Действия** (каждое идемпотентно и подтверждаемо): заменить модель в пуле, повторить синтез, обновить каталог (Actualize), применить миграции, перезапустить воркер (**только** если unit объявляет авто-перезапуск), открыть Raw-запись события.
4. **Самодиагностика системы в этом же экране** — устаревший код воркера, состояние миграций и версий схемы, права на записываемые каталоги, свежесть каталога, инвариант «пул и роли ⊆ активный каталог».
5. **После действия** — перепроверить состояние и показать результат честно (что изменилось, что нет).

## Вне объёма

Полноценная панель здоровья как отдельная страница (R-7), планировщик (R-6), дашборд расходов (R-5).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых зависимостей; git не трогать. JS: только `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены (`tests/CssTokensTest.php`).
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Опасные действия (перезапуск, миграции) обязаны быть подтверждаемыми и журналируемыми; никаких «тихих» починок.
- `node --check` для ESM бесполезен — проверять через копии `.mjs`.

## Критерии приёмки

- Для каждого класса отказа есть причина и хотя бы одно действие; после действия состояние перечитывается.
- Действия не выполняются молча: подтверждение и запись в журнал.
- Оператор может объяснить сбой, не открывая логи и Raw-события (Raw остаётся доступен как детализация).

## Проверка

```
php -l <изменённые .php>; node --check <копии .mjs>
php tests/TerminalStatusTest.php        # 43 / 0 — факты вердикта
php tests/ChatStreamDomTest.php         # 8 / 0
node --experimental-vm-modules tests/harness/chat-stream.mjs   # 140 / 0
php tests/SmokeTest.php                 # 1534 / 54, набор падений не растёт
php tests/AdminKeyProtectionTest.php    # 84 / 0 — действия под админ-гейтом
```
Новое: проверки классификации причин и отображения блока — модульно и в харнессе; проверка, что каждое действие идемпотентно (повторный вызов не ломает состояние).

## Заливка

`. \deploy\host\deploy.ps1 -Mode plan | -Mode deploy` (бэкап + `php -l` + перезапуск воркеров); откат `-Mode rollback -BackupId <id>`.
