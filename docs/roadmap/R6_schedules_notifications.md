# R6 — Расписания и уведомления для длинных работ

ROLE: Senior backend engineer specialised in job scheduling and delivery integrations (PHP 8.5, systemd, webhooks). Ты умеешь сделать так, чтобы длинная работа пережила перезапуск и один раз сообщила о результате.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок. Работа выполняется воркером (`bin/revoap-worker.php`, systemd: `revoap-worker`, `revoap-worker@1`, `revoap-worker@2`). Синхронный прогон может идти до двух часов, пакетный — до 24 часов (окно провайдера). Сейчас результат виден только тому, кто держит вкладку открытой.

## Что уже есть

- Очередь: `revoap_jobs` (`status`, `attempts`, `max_attempts`, `heartbeat_at`, `next_run_at`, `result_json`), маркеры `payload.kind`: `pipeline`, `models_actualize`, `batch_pipeline`, self-test.
- Планирование: воркер поднимает задачу по `next_run_at`; есть парковка задачи (`JobRepository::parkUntil`) и восстановление после обрыва (`requeueForInfrastructure`, `rearmParked`).
- Вебхуки: `src/Api/Webhook*.php` (подписки, доставки, повторы) — существующий канал уведомлений.
- История: `council_sessions`, `HistoryService`, share-страница (ссылка на прогон).
- Диагностика воркера: `WorkerHealthService` (`last_job`, `code_state`, heartbeat по presence).

## Цель

Задание можно поставить на расписание, а о завершении или сбое приходит уведомление — без открытой вкладки.

## Объём работ

1. **Расписание** — один раз / ежедневно / по cron-выражению; для прогона-запроса (с шаблоном из R-4, если он есть) и для запуска актуализации каталога. Хранить рядом с существующими настройками; переживать перезапуск воркера.
2. **Идемпотентный запуск** — не создавать второй прогон, пока идёт предыдущий; при совпадении времени писать, что пропущено и почему.
3. **Уведомления** — канал по выбору: вебхук, письмо или мессенджер (использовать существующие интеграции, не изобретать транспорт). Один исход — одно уведомление, с ссылкой на прогон и краткой сутью (статус, стоимость, длительность, состав, арбитр).
4. **Хвосты** — уведомление о провале должно содержать причину из терминального вердикта (`status_reason`, `status_detail`), а не только «failed».
5. **Отмена и пауза** — расписание можно выключить; уже запущенный прогон управляется как обычно (Cancel).

## Вне объёма

Полноценный календарь задач по типу корпоративного планировщика, уведомления между пользователями (многопользовательский режим вне очереди).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. Публичные контракты API только дополнять.
- Миграции — только новый файл `db/migrations/NNN_*.sql` с `@table-version`, идемпотентно.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Секреты (ключи вебхуков, SMTP) — только через существующие механизмы хранения; в логи не писать.
- Уведомление обязано иметь признак «уже отправлено», иначе переподнятие задачи даст дубль.

## Критерии приёмки

- Настроенное расписание переживает перезапуск воркера; пропуск запуска объясняется.
- Уведомление приходит один раз на исход и содержит ссылку на прогон.
- Провал уведомляет с причиной, а не общим «failed».
- Отключение расписания не влияет на идущие прогоны.

## Проверка

```
php -l <изменённые .php>
php tests/JobSessionReuseTest.php       # 34 / 0
php tests/WorkerStatusTest.php          # 157 / 0
php tests/WorkerFeedsTest.php           # 78 / 0
php tests/DatabaseResilienceTest.php    # 81 / 0
php tests/SmokeTest.php                 # 1534 / 54, набор падений не растёт
```
Новое: расчёт следующего запуска (включая переходы суток и пропуски), идемпотентность уведомления, поведение при перезапуске воркера — фикстурами и сценариями без сети.

## Заливка

`. \deploy\host\deploy.ps1 -Mode plan | -Mode deploy`; миграцию применить через «Apply Migrations». Откат — `-Mode rollback -BackupId <id>`.

## Отчёт исполнителя

Формат хранения расписаний, как считается следующий запуск, как обеспечена однократность уведомления, команды с exit-кодами, что не проверено (реальные SMTP/вебхуки).
