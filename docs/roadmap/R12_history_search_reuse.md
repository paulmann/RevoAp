# R12 — Поиск и переиспользование в истории (текстовый и смысловой)

ROLE: Senior full-stack engineer specialised in retrieval (full-text and vector search) with retrieval UX sense (PHP 8.5 + vanilla JS).

## Контекст проекта

ReVoAp — self-hosted консенсус-движок. В истории накапливаются прогоны: вопрос, состав и арбитр, шаги, вердикт, финальный ответ, статистика. Найти нужное сейчас можно только глазами по списку.

## Что уже есть

- История: `council_sessions`, `council_steps` (в том числе `summary` с текстами ответов), `council_model_responses`, `pipeline_events`; `src/History/HistoryService.php`; вкладка History с деталями и фильтрами.
- Векторное хранилище: `src/Storage/VectorStore.php`, `src/Storage/Vector/*` (Qdrant и локальные реализации), `src/Memory/*` (эмбеддинги, `EmbeddingMemory`), настройки памяти.
- Кеш ответов моделей: `ModelResponseCache` (не путать с поиском — это кеш повторов).
- Публикация: share-страница прогона.

## Цель

История должна быть кладовой, из которой достают: найти прогон по фразе из ответа или по смыслу и переиспользовать его.

## Объём работ

1. **Полнотекстовый поиск** по вопросам и ответам (включая `summary` шагов и финальные ответы) с подсветкой совпадения и переходом к нужному шагу.
2. **Смысловой поиск** — через существующее векторное хранилище и эмбеддинги; обязательная деградация: если векторная часть недоступна, текстовый поиск продолжает работать, а интерфейс говорит, что смысловой режим недоступен.
3. **Фильтры** — период, домен/совет, модель-участник, статус (в том числе Error), есть ли финальный ответ; комбинируются с поиском.
4. **Переиспользование** — «повторить этот вопрос» (с текущим пулом), «подставить состав этого прогона», «открыть шаг и модель, которые дали ответ».
5. **Честность** — если смысловой поиск не включался или индекс устарел, это видно; «ничего не найдено» не должно означать «поиск не работал».

## Вне объёма

Поиск по чужим прогонам (многопользовательский режим вне очереди), выгрузка всей истории (это R-8).

## Ограничения и конвенции репозитория

- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать. JS: `el()`/`textContent`, `innerHTML` запрещён. CSS: только существующие токены.
- Миграции — только новый файл `db/migrations/NNN_*.sql` с `@table-version`, идемпотентно; индексы для поиска добавлять там же.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- Смысловой поиск расходует деньги на эмбеддинги: расход должен быть виден оператору, индексация — не на каждый запрос.

## Критерии приёмки

- Поиск находит прогон по фразе из ответа и открывает нужный шаг.
- Смысловой режим работает при доступном хранилище и честно сообщает о недоступности при отсутствии.
- «Повторить вопрос» создаёт новый прогон с текущим пулом и показывает новый состав.
- Отсутствие результатов не маскирует сбой поиска.

## Заливка

`. \deploy\host\deploy.ps1 -Mode plan | -Mode deploy`; миграцию применить через «Apply Migrations». Откат — `-Mode rollback -BackupId <id>`.

## Отчёт исполнителя

Как устроен поиск (индексы, запросы), как обеспечена деградация, что стоит денег, команды с exit-кодами, что не проверено (объём истории, качество смыслового поиска).
