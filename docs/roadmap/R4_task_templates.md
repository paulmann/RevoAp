# R4 — Библиотека шаблонов задач (пул + совет + настройки в один клик)

ROLE: Senior product engineer (frontend-heavy) with solid PHP 8.5 and domain-modelling skills. Ты умеешь сделать повторяющуюся работу в один клик и не плодишь второе хранилище тех же данных.

## Контекст проекта

ReVoAp — self-hosted консенсус-движок (PHP 8.5, без фреймворка). Перед запуском оператор собирает в левой панели пул моделей, выбирает совет («Consensus skill») и настройки прогона (reasoning, лимит циклов, режим синхронный/пакетный).

## Что уже есть

- Пресеты доменов: `domain_presets.definition_json` = `{models[], arbiter, skill_slug}`; вкладка Models умеет применять пресет к панели (`applyPresetToSelection` в `assets/js/model-selector.js`).
- Привязка «совет → модели»: `GET /api/consensus/skills` отдаёт на каждый скилл `preset`, `models`, `arbiter`, `uses_user_pool`; чат применяет её при выборе совета.
- Панель выбора моделей: комбобокс с поиском внутри списка, галочка «Show all models», счётчик состава, batch-режим.
- Скиллы живут файлами в `src/Skills/definitions/*.json`; каталог скиллов для интерфейса собирает `src/Skills/ConsensusSkillCatalog.php`.
- Настройки прогона: `reasoning`, `cycle_limit`, `run_mode` (`batch`), выбор скилла; отправка идёт в `/api/council/jobs`.

## Цель

Именованный шаблон = подсказка-каркас + совет + пул + арбитр + настройки → применяется одним действием и воспроизводит конфигурацию прогона.

## Объём работ

1. **Модель шаблона** — идентификатор, название, описание, каркас подсказки, ссылка на совет (`skill_slug`), пул моделей, арбитр, reasoning, лимит циклов, режим. Хранение — рядом с существующими настройками, без второго источника истины для пула/пресета (шаблон ссылается на пресет или хранит собственный список — выбери и обоснуй).
2. **Интерфейс** — список шаблонов рядом с чатом, применение в один клик (пул + совет + настройки), создание «из текущего состояния», переименование, удаление, экспорт/импорт.
3. **Редактор привязки «совет → пул»** — сейчас привязка задаётся пресетом и только читается; дать оператору менять пул для совета и сохранять это.
4. **Честность применения** — если часть моделей шаблона недоступна у настроенных коннекторов, назвать их поимённо и не делать вид, что всё применилось (тот же контракт, что у `applyPreset`: `{applied, skipped, empty, reason}`).
5. **Прогон не менять** — тело запроса к `/api/council/jobs` остаётся прежним.

## Вне объёма

Магазин шаблонов между пользователями (вне очереди), автоматический подбор шаблона по тексту запроса (это может стать отдельным пунктом).

## Ограничения и конвенции репозитория

- JS: только `el()` / `textContent`, `innerHTML` запрещён. CSS: только существующие токены из обеих тем (`tests/CssTokensTest.php`).
- PHP: `strict_types`, `final class`, PHPDoc; без новых Composer-зависимостей; git не трогать; публичные контракты API только дополнять.
- Не трогать `.dev_agent/**`, `archive/**`, `vendor/**`, `Consensus-AI-main/**`, `cache/**`, `logs/**`, `assets/js/copy_to_clipboard.js`, `deploy/host/**`.
- `node --check` для ESM бесполезен — проверять через копии `.mjs`.

## Критерии приёмки

- Шаблон применяется одним действием и воспроизводит пул, совет и настройки; повторное применение идемпотентно.
- Привязка «совет → пул» редактируется в интерфейсе и сохраняется, при этом существующее поведение по умолчанию не меняется.
- Недоступные модели шаблона называются поимённо.
- Структура хранения не дублирует пул/пресет так, чтобы они могли разойтись.
